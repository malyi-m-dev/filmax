# Filmax — правила проекта

Клиент kino.pub для телефона и Android TV: один APK, два графа навигации (`MainActivity` ветвится
по `FEATURE_LEANBACK`). Data/domain — Kotlin Multiplatform, iOS-презентейшен — SwiftUI в `iosApp/`.
Архитектура и стек — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), TV — в [docs/TV.md](docs/TV.md), подробный свод
читаемости — в [docs/refactoring-guidelines.md](docs/refactoring-guidelines.md). Здесь — правила,
которые нельзя нарушать, и то, как проверять работу.

## Архитектура

- Зависимости однонаправленные: `app → feature → core/data → core:domain`.
- Фича = `feature:<x>:common` (ScreenModel, Contract, Koin-модуль, без UI) + `:mobile` + `:tv`.
  Логика экрана не дублируется между платформами, UI — раздельный.
- MVI на `BaseScreenModel<State, SideEffect, Event>`: события — через `dispatch(Event)`, State —
  неизменяемый снимок, SideEffect — одноразовые эффекты. Репозиторий отдаёт `RequestResult<T>`
  через `safeRequest` — никаких try/catch в ScreenModel.
- Навигация: экран не получает колбэков навигации и не знает `NavController`. Он называет адрес
  (`Destination`) и отдаёт его `Navigator` (`open` / `replace` / `root` / `back`). Адрес
  превращается в маршрут только в `:app` — таблицами `PhoneRoutes` и `TvRoutes`.
- `data` и `core:domain` — `commonMain` (Ktor, multiplatform-settings), в iOS уходят через
  `:shared` + SKIE. `core:presentation` и `feature:*:common` — только Android. iOS — SwiftUI,
  не Compose Multiplatform.
- DI — Koin. Диспетчеры инжектятся; прямой `Dispatchers.IO` допустим только в DI-модуле.

## Дизайн-система

- Кнопки, чипы, бейджи, карточки, поля, кнопка «назад» — готовые компоненты `Filmax*` в
  `core:ui` (на ТВ — `Tv*` в `core:tv-designsystem`) с минимальным API. Экраны собираются из них;
  своя вёрстка кнопки или бейджа на экране — запрещена. Нужен новый элемент — сначала компонент
  в `core:ui` и его витрина в `feature:designsystem`, потом экран.
- Размеры и цвета — из токенов (`FilmaxMetrics`, `TvMetrics`, тема). Разовые `dp` — именованной
  константой файла, не россыпью по дереву.
- Монохром: нейтральная палитра, акцент — белый, цвет на экране только у постеров и кадров;
  приглушённый красный — только ошибки и деструктив. Формы — скруглённый прямоугольник и круг.
  ТВ-фокус — белая рамка, тёмный ореол и scale.
- Разделы на обеих платформах: Главная · Каталог · Моё · Профиль.

## Код

- Никаких однобуквенных и обрезанных имён (`s`, `f`, `c`, `dl`) — ни в лямбдах, ни в циклах, ни
  в деструктуризации. Полное имя по смыслу или `it`, если параметр один и scope короткий.
  Однобуквенные ловит detekt-правило `SingleLetterName` (модуль `:detekt-rules`), сокращения — ревью.
- Функция — одна задача; ориентир ≤ 30 строк (Composable ≤ 50), жёсткий предел detekt — 60.
  Вложенность ≤ 3: guard clauses, ранний `return`, `when` вместо лестниц `if`.
- Больше пяти параметров — объект-параметр (`*Actions`, срез state). Никаких `!!`; магические
  числа — в именованные константы; коллекции — операторами, а не циклами с накоплением.
- Комментарии и KDoc — по-русски и про «почему», а не «что». При переносе кода их сохраняют и
  обновляют; устаревший комментарий хуже отсутствующего.
- Большой экран раскладывается по файлам: каркас и состояние / секции / карточки / диалоги, как
  в `feature/details/tv` и `feature/library/tv`. Перенос не меняет поведение, видимость
  расширяется до `internal` только там, где вызов пересёк границу файла.
- detekt-baseline'ы пустые и должны оставаться пустыми. `@Suppress` — только с комментарием,
  почему правило здесь неприменимо.

## ТВ: фокус

- Ряд, сетка, панель чипов — `Modifier.tvFocusGroup()` (штатный `focusRestorer` + `focusGroup`).
  Исключение — `TvRail`: память у него своя (`focusProperties.enter`), и каждая карточка ряда
  отмечается `Modifier.tvRailEntry(index)`. Тогда первый вход в ряд — на первую карточку, а
  возврат — на ту, с которой ушли, даже если ушли явным `focusProperties`.
- Стартовый фокус экрана и возврат туда, откуда ушли на другой экран, — `rememberTvScreenFocus()`:
  `containerModifier` на корневой контейнер, `focus.item(key)` на каждую карточку. Фокус ставится
  по `onPlaced`, без ожиданий по кадрам.
- Вкладки попапятся до корня раздела (`HomeRoute` / `TvHomeRoute`), а не `findStartDestination()`:
  старт графа — сплэш, которого после входа в стеке нет.

## kino.pub: инварианты

- `PlayerRoute(itemId, videoId, season)`: `videoId` — номер серии внутри сезона, уникален только
  в сезоне, поэтому сезон обязателен везде, где запускается серия.
- `watching.status`: −1 — не начат, 0 — в процессе, 1 — досмотрен.
- Другая серия — это навигация (`navigator.replace`), а не подмена `MediaItem`: прогресс пишется
  в трек, выбранный при старте плеера.
- DTO — с nullable по умолчанию: API пропускает поля и присылает дробные числа там, где ждёшь
  целые (`api/v1/user` без `id`, `days` = 6.1). Одно обязательное поле роняет весь парсинг.

## Проверка

- Перед коммитом: `./gradlew detekt detektMain :app:assembleDebug testDebugUnitTest` — ровно то,
  что гоняет CI. `detektMain` с type resolution ловит больше обычного `detekt`.
- UI проверяется вживую на mock-сборке: `./gradlew :app:installMock` — без бэкенда kino.pub и
  без входа, данные из `:data:fake` (опорные id — в `FakeIds`: сериал на 7 сезонов, серии без
  кадров, подборка на 45 тайтлов). Живой kino.pub на эмуляторах упирается во вход и режется DPI.
- Телефон — отдельный AVD (рабочий `Pixel_4` не трогать), ТВ — AVD `Television_1080p`: на
  телефонном эмуляторе приложение показывает мобильный UI. ТВ — основная платформа: фича без
  указания платформы проверяется сначала на нём.
- Новая логика — с юнит-тестом в `src/test` (или `commonTest` у KMP-модуля): зависимости
  раздают convention-плагины, ScreenModel тестируется на фейках из `:data:fake`.

## Git и changelog

- Ветка от `master` → PR → зелёный CI → merge. Стек-PR мержится в `master`, а не в родительскую
  ветку стека.
- Conventional Commits по-русски: `refactor(tv): …`, `fix(collections): …`. Тело — что было
  не так и почему решение такое; для UI — строка «Проверено на …».
- Заметное изменение — абзац в `CHANGELOG.md` → `## [Unreleased]` (Добавлено / Изменено /
  Исправлено) языком для человека, а не списком классов.
- Релиз — пуш тега `vX.Y.Z`: CI собирает подписанный APK и публикует GitHub Release.
- Репозиторий публичный: `local.properties`, `keystore.properties`, `google-services.json` и
  ключи не коммитятся никогда.
